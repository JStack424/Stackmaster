# Stackmaster 1.3.4 live test checklist

Rollback if any regression blocks play: **remove 1.3.4 and return to Stackmaster 1.2.0.**

- [ ] **Inventory row position** — Open the inventory with at least one ordinary reservation. Expected: the row is exactly 20 logical UI pixels above its rendered 1.3.3 position, keeps the 12-pixel right shift, and remains safely bounded at different UI scales and resolutions.
- [ ] **Reservation-without-materials text** — Reserve an ordinary piece with no complete material set nearby. Expected: compact white upper-left text reads `Stackmaster:` then `• Reserved <piece> ×<total> — materials not gathered.`; no large yellow success notice appears.
- [ ] **Inventory-card selection** — Click an ordinary reservation card with and without the Hammer active. Expected: it selects only when the Hammer is active, never removes/decrements, and never auto-equips a tool.
- [ ] **Hammer-menu row** — Open the Hammer menu with an ordinary reservation and select its card. Expected: the mirrored row sits directly above the live menu and selection follows Valheim’s ordinary sound, close, and placement transition.
- [ ] **Dedicated removal controls** — Exercise `-` with multiple counts and `X` with the final count. Expected: each click durably releases exactly one, refreshes both rows and orange allocation immediately, cancels one matching uncommitted gather, moves no materials, and never clicks through or selects the card.
- [ ] **Placement decrement** — Place one ordinary reserved piece successfully, then try a failed/cancelled preview. Expected: only the authoritative successful local placement decrements exactly one; failed/cancelled placement and selection do not.
- [ ] **Stack/Pile full gather** — Use modified Quick Grab on vanilla and, if available, modded pieces with localized names such as `Wood Stack`, `Stone pile`, mixed-case variants, and compound names such as `Woodpile`, while one complete recipe is reachable. Expected: the full set gathers with ordinary `grabbed materials` feedback, but no reservation record/card/count, additive Quick Stack target, orange quantity, reservation-first sorting, or later placement decrement appears.
- [ ] **Stack/Pile shortage and reachability** — Repeat with zero stock, one unit short, unreachable/busy storage, insufficient slots, and insufficient carry weight. Expected: nothing moves, no partial materials move, no reservation is created, and the ordinary truthful failure appears; there is no `Reserved … materials not gathered` success notice.
- [ ] **Name authority and fallback** — Check an unrelated piece and any modded/localized examples available. Expected: matching uses the player-visible localized name case-insensitively; raw localization token or exact prefab name is consulted only when localization is unavailable. Unrelated localized names remain ordinary reservable pieces.
- [ ] **Existing-record cleanup** — If a prior test profile contains a resolved Stack/Pile reservation, load/refresh it. Expected: Stackmaster removes it from persistence, both rows, Quick Stack targets, orange allocation, and reservation sorting without moving or depositing carried materials. An unresolved historical piece remains untouched rather than being guessed.
- [ ] **Lifecycle** — Open/close the inventory and Hammer menu, switch tools, change UI scale/resolution, reconnect, and change worlds. Expected: no stale rows, no brief reappearance after closure, no cross-character/world state, and cleanup remains stable.
- [ ] **1.3.3 regression pass** — Recheck Quick Stack, replenishment, ordinary reservation orange attribution, reservation-first sorting, and touched-chest auto-sort. Expected: every previously passing 1.3.3 path remains unchanged for non-Stack/Pile pieces.
